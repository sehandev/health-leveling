# 2026-10-19 작업 기록

## 1. 제품 및 도메인 방향 정리

건강 기록, AI/계산 기반 파생 데이터, 화면 표시용 `Presentation Model`을 별도 개념으로 정리했다. 한국어 UI와 영어 canonical domain terms를 병행하고, 장소는 `Place`로 통일해 집·식당·체육관을 포괄하며, InBody 결과는 단일 값이 아니라 개별 `Body Metrics`로 기록하기로 했다. XP는 감소하지 않고 레벨당 필요 XP는 고정한다. 세부 XP 계산과 일부 측정 필드 명칭은 미결정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md)

## 2. Cloudflare와 로컬 Pi 연결 방향 결정

Wrangler가 아니라 설치된 `cf` CLI를 Cloudflare 작업의 기본 도구로 사용한다. 현재 버전은 `v1.0.0-beta.18`이므로 버전을 고정하고 업그레이드 시 명령 호환성을 확인한다. 개발 Mac의 Pi CLI RPC는 네트워크 서버가 아니므로 로컬 HTTP bridge가 필요하다. Worker에서 Cloudflare Tunnel과 Access를 거쳐 bridge에 연결하며, Mesh는 Worker에서 Mac으로 직접 연결하는 경로로 사용하지 않는다.

상세 문서: [Cloudflare CLI and Local Pi Bridge](../docs/cloudflare-cli.md)

## 3. 완성까지의 단계 분해

완료까지의 작업을 Product Definition, Platform Foundation, Identity/Data Foundation, Core Logging, XP/Leveling, Dashboard/Progress, AI Insights, Release Readiness로 나눠 [Product Roadmap](../docs/roadmap.md)에 기록했다. Mac의 Pi와 Tunnel 연결은 구현 리스크가 있으므로 초기에 짧게 검증하고, 앱의 기본 기록 흐름은 AI 없이도 동작하도록 순서를 잡았다. 수동 기록과 성장 루프를 우선 출시하는 MVP cut line은 제안일 뿐 아직 확정하지 않았다.

## 4. 첫 출시 범위 결정

첫 출시는 개인용 단일 사용자 앱으로 하고, 가입·다중 사용자 기능은 우선 제외한다. 반면 기능 범위는 축소하지 않고 식사·영양제·운동·신체 지표·목표·사진, 성장 시스템, AI를 첫 완성 버전에 포함한다. Roadmap phase는 기능을 뒤로 미루기 위한 MVP cut이 아니라 구현 순서다. AI는 우선 Mac의 Pi와 Tunnel에 의존하므로 Mac이 오프라인이면 사용할 수 없고, 원격 접속 시 접근 제어 방식은 아직 정하지 않았다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md), [Cloudflare CLI and Local Pi Bridge](../docs/cloudflare-cli.md)

## 5. Daily Touchpoints 결정

하루 흐름을 하나의 일일 체크인으로 묶지 않고, 기상 후·아침 식사 후·점심 식사 후·저녁 식사 후·운동 전·운동 후·취침 전의 일곱 contextual touchpoint로 나누기로 했다. 이들은 필수 순서나 고정된 시간표가 아니며, 해당되지 않는 touchpoint를 건너뛰어도 XP를 차감하지 않는다. 각 시점에 제공할 기록·액션·추천과 알림 여부는 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 6. Wake-up의 신체 정보와 Today’s Status 논의

Wake-up에서 현재 `Body Weight`와 `Height`를 함께 보여주고 둘 다 수정 가능하게 한다. 변경 없이 진행하면 저장된 값을 유지하며 별도 skip 버튼은 필요하지 않다. `Today’s Status`에는 목표, 운동 계획, 영양·영양제 진행도, 최근 신체 지표, XP/레벨, 미기록 항목, AI insight 등이 후보이나 구성은 아직 결정하지 않았다. 기록 전의 미입력 값을 실패나 의미 있는 0으로 표시하지 않는 원칙을 문서화했다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 7. Wake-up 흐름 구체화 및 앞선 결정 정정

Wake-up에서는 `Height`를 매일 보여주거나 수정할 필요가 없다고 정정했다. 이제 흐름은 editable `Body Weight` → 14일 일간 체중 그래프 → 현재 `Avatar` level/XP → 14일 일간 level/XP 그래프 → 단일 `Next Best Action` 순서다. 체중 미측정일 표시 방식과 XP 그래프의 XP 단위·축·시각화 방식은 아직 정하지 않았다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 8. Wake-up 그래프 결정 및 기록 의미 정정

미측정일은 별도로 두지 않는다. Wake-up에서 값 변경 없이 진행해도 해당 날짜의 `Body Weight` 기록을 저장값으로 생성한다. 따라서 14일 체중 그래프는 매일 값을 표시한다. 두 그래프는 같은 디자인을 사용하고, 체중은 표시 단위 5 간격, 성장 그래프는 누적 XP line과 `Avatar` Level step line으로 정했다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 9. Next Best Action의 시간 범위

`Next Best Action`은 지금 당장 시작할 일을 지시하는 것이 아니라 오늘 중 적절한 시점에 하면 좋을 한 가지 행동을 제안한다. 예를 들어 오늘 예정된 운동이나 다음 식사에서 할 행동이 될 수 있다. 선택 우선순위, 입력 신호, AI와 규칙 기반 판단의 역할, 적합한 후보가 없을 때의 fallback은 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 10. Next Best Action 정책 선택

`Next Best Action`은 오늘 중 수행할 행동을 제안하며, 우선순위는 `Balanced`로 정했다. 즉 오늘 계획된 행동과 활성 목표를 향한 진전을 함께 고려한다. 구체적인 입력 신호, 우선순위 가중치, 동률 처리, AI/규칙 기반 로직의 역할은 아직 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 11. Primary Goal 선택 방식

활성 `Goal` 중 사용자가 하나를 `Primary Goal`로 지정하기로 했다. `Next Best Action`의 `Balanced` 우선순위는 오늘의 계획과 함께 이 주 목표를 고려한다. 구체적인 ranking signal과 tie-breaker는 아직 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 12. Primary Goal이 없는 경우의 Wake-up 분기

`Primary Goal`이 없으면 `Next Best Action` 대신 Goal을 설정할 수 있는 선택지를 바로 제시한다. 제시할 적절한 선택지가 없다면 당일 `Plan`만 보여주고 Wake-up 흐름을 마친다. `Plan`은 운동 `Program`과 구별되는 오늘의 예정 활동으로 용어집에 추가했다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 13. Goal setup choice 확정

초기 Goal setup 선택지를 `Target Body Weight`, `Target Body Fat Percentage`, `Muscle Gain`, `Performance Goal` 네 가지로 정했다. 각 유형의 입력 필드·측정 단위와 Goal 생성 후 `Primary Goal`로 설정되는 흐름은 별도 결정이 필요하다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 14. Target Body Weight 필드 결정

`Target Body Weight` Goal에는 target value와 `Target Date`만 둔다. 별도 start value는 저장하지 않는다. 다른 Goal Type들의 세부 필드와 목표 진행도 산정 방식은 아직 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 15. Target Body Fat Percentage 필드 결정

`Target Body Fat Percentage` Goal에도 target percentage와 `Target Date`만 둔다. 별도 start value는 저장하지 않는다. `Target Body Weight`와 같은 입력 구조를 사용한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 16. 근육 목표 입력 방식 결정

일반적인 `Muscle Gain`은 측정 가능한 target value 없이 `Target Date`만 둔다. InBody에서 얻는 whole-body `Skeletal Muscle Mass`는 target value와 `Target Date`를 설정할 수 있다. 이 측정 가능한 근육량 목표를 독립 `Goal Type`으로 둘지 `Muscle Gain`의 하위 선택으로 둘지는 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 17. InBody 근육량 목표의 Goal 구조

InBody whole-body `Skeletal Muscle Mass`는 독립된 다섯 번째 top-level `Goal Type`이 아니라 `Muscle Gain`의 하위 선택지로 두기로 했다. `Muscle Gain`에는 날짜만 있는 일반 목표와 target value 및 `Target Date`가 있는 InBody 측정 목표가 포함된다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 18. Performance Goal 필드 결정

`Performance Goal`은 target performance value와 `Target Date`를 저장하고, 별도 start value는 저장하지 않는다. 기록된 workout history를 관측된 진행 상황으로 사용한다. 구체적인 performance metrics와 units는 아직 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 19. Performance Goal 지표 범위 결정

Performance Goal은 앞서 논의한 모든 지표 유형을 지원한다: `Load`, `Reps`, `Distance`, `Duration`/time, `Pace`. 목표에는 metric/value와 unit, `Target Date`가 있고 별도 start value는 없다. 진행 상황은 workout history에서 읽는다. 구체적인 단위 선택은 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 20. Performance Goal 기본 단위 결정

초기 기본 단위는 `Load` kg, `Distance` km, `Duration` 초/분(표시 크기에 적합한 단위), `Reps` 개수, `Pace` min/km로 정했다. 다른 단위는 필요할 때 추가한다. 내부 저장 시 정규화 단위는 아직 미정이다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 21. Performance Goal 다중 지표

하나의 `Performance Goal`에서 복수의 metric/value를 함께 목표로 둘 수 있다. 예: 달리기 목표에 `Distance`와 `Duration`을 함께 지정한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 22. 복합 Performance Goal 완료 조건

복수 metric을 포함하는 `Performance Goal`은 모든 target condition을 만족해야 완료로 본다. 예를 들어 달리기 Goal의 `Distance`와 `Duration` 조건을 모두 달성해야 한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 23. Performance Goal 달성 방향 기본값

적당한 기본 비교 방향을 정하고 Performance Goal 설계를 일단 닫았다. `Load`, `Reps`, `Distance`, 플랭크 같은 hold `Duration`은 target 이상, 완주 시간과 `Pace`는 target 이하를 기본으로 한다. `Duration`의 방향은 활동 맥락에 따른다. 복합 목표는 모든 조건을 만족해야 한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 24. Daily Plan 구성 결정

`Plan`은 별도 full-featured planner가 아니라 기존 일정의 집합으로 구성한다. `Program`의 운동 일정과 예정된 supplement routine을 자동으로 포함하고, 사용자가 다른 행동을 수동으로 추가할 수 있다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 25. Meal logging과 on-demand recommendation 구분

Meal을 기록한 직후에는 AI nutrition analysis만 보여주고 meal flow를 종료한다. 다음 식사 보완 조언은 자동으로 띄우지 않는다. 사용자가 직접 요청할 때 meal records와 Goals를 바탕으로 meal/menu recommendation을 제공한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)

## 26. Empty Meal Slot action

아직 기록하지 않은 `Meal Slot`을 누르면 modal `Action Sheet`를 띄워 `Menu Recommendation`과 `Log Meal`을 선택하게 한다. 추천은 사용자가 직접 요청한 경우에만 열리고, 메뉴 추천을 선택한 것만으로 식사를 먹었다고 기록하지 않는다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 27. Menu Recommendation Session 기록

빈 `Meal Slot`의 `Menu Recommendation` action은 별도 page를 열어 AI가 1–3개 메뉴를 순위와 이유와 함께 제시한다. 입력은 이전 Meal records, 현재 body metrics, active goals, 현재 시각, 남은 식사 슬롯이다. 종료 시 input snapshot, AI output, 선택한 rank 또는 no selection을 저장해 이후 추천에 활용한다. 이 action은 Meal, `Draft`, `Plan`에 데이터를 쓰지 않는다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 28. Meal Entry Mode 분리 및 receipt parsing

`Log Meal`의 입력 방식을 `Meal Photo`, `Receipt/Order Import`, `Manual Food Item Entry`로 분리한다. Receipt/Order Import는 AI가 candidate `Food Items`를 추출하고, 사용자가 확인·수정·삭제·추가한 뒤 확정해야 meal record로 저장한다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 29. Meal Photo AI extraction 및 PDF 제외

`Meal Photo`도 AI가 candidate `Food Items`를 추출한다. 메뉴/브랜드까지 알아보면 구체적으로 제시하고, 그렇지 않으면 일반 음식명으로 제시한다. 사용자가 검토·수정·추가·삭제한 뒤에만 저장한다. `Receipt/Order Import`도 같은 review flow를 사용하되 이미지 파일만 지원하고 PDF는 지원하지 않는다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 30. Receipt/Order source image 보존

영수증·주문서 이미지 원본은 AI extraction 후 버리지 않고, 사용자가 Meal record를 확정하면 해당 Meal의 source image로 보관한다. PDF는 지원하지 않는다.

상세 문서: [Product Concept](../docs/product-concept.md), [Domain Glossary](../docs/domain-glossary.md), [Product Roadmap](../docs/roadmap.md)

## 31. Meal 삭제 시 연관 이미지 삭제

Meal을 삭제하면 해당 Meal에 속한 모든 이미지도 삭제한다. Meal photo와 보관 중인 receipt/order source image가 모두 포함된다. 따라서 Meal deletion과 이미지 정리는 하나의 삭제 동작으로 다뤄 고아 파일을 남기지 않는다.

상세 문서: [Product Concept](../docs/product-concept.md), [Product Roadmap](../docs/roadmap.md)
